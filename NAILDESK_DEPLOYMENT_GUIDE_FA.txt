          (ویژهٔ ویندوز ۱۱ و انتشار روی GitHub Pages)

این راهنما برای کسی نوشته شده که آشنایی کمی با GitHub یا توسعهٔ وب
دارد. همهٔ مراحل شماره‌دار و قدم‌به‌قدم هستند و فقط به چیزهایی اشاره
می‌کنند که واقعاً در پروژه وجود دارند. هیچ فایل یا دادهٔ شخصیِ
مشتری‌ها نباید به GitHub فرستاده شود — این نکته در طول راهنما تکرار
می‌شود.


──────────────────────────────────────────────────────────────────────────
بخش A — باز کردن NailDesk روی ویندوز ۱۱
──────────────────────────────────────────────────────────────────────────

دو راه برای باز کردن برنامه روی ویندوز وجود دارد.

▂▂▂ روش ۱: باز کردن وب‌سایت منتشرشده (ساده‌ترین راه) ▂▂▂

پس از انجام مراحل انتشار (بخش‌های B و C)، آدرس نهایی برنامه چیزی شبیه
این خواهد بود:

    https://USERNAME.github.io/naildesk/

(به‌جای USERNAME نام کاربری گیت‌هاب شما می‌نشیند — بخش C را ببینید.)

  ۱. مرورگر Chrome یا Edge را باز کنید؛
  ۲. همین آدرس را در نوار آدرس تایپ و Enter بزنید؛
  ۳. برنامه کامل بارگذاری می‌شود و همهٔ بخش‌های آن (خانه، مشتری‌ها،
     تقویم، طراحی، گالری، تنظیمات) کار می‌کنند.

نکتهٔ مهم: رایانه، «بانک اطلاعاتی محلیِ خودش» را دارد که با آیفون
هم‌گام نمی‌شود. یعنی داده‌هایی که روی ویندوز وارد کنید فقط روی همان
رایانه می‌مانند و داده‌های آیفون هم فقط روی آیفون. برای انتقال بین
دستگاه‌ها فقط از فایل پشتیبان JSON استفاده کنید (بخش G).

▂▂▂ روش ۲: اجرای پروژه به‌صورت محلی (برای توسعه یا تست) ▂▂▂

پیش‌نیازها: ویندوز ۱۱، اینترنت، و فایل ZIP سورس پروژه
(NAILDESK_FINAL_GITHUB_SOURCE.zip).

  ۱. نصب Node.js:
     به سایت رسمی nodejs.org بروید، نسخهٔ LTS (در زمان نگارش، ۲۰ یا
     ۲۲) را برای ویندوز ۶۴بیتی دانلود و با گزینه‌های پیش‌فرض نصب
     کنید. پس از نصب، منوی استارت را باز کنید، «PowerShell» را تایپ
     کنید و Enter بزنید. در پنجرهٔ آبی که باز می‌شود بنویسید:

         node --version

     اگر شمارهٔ نسخه (مثلاً v20.11.0) چاپ شد، نصب درست بوده است.

  ۲. خارج‌کردن سورس از حالت فشرده:
     روی فایل NAILDESK_FINAL_GITHUB_SOURCE.zip راست‌کلیک کنید و
     «Extract All…» را بزنید. پوشهٔ حاصل مثلاً این مسیر را دارد:

         C:\Users\YOURNAME\naildesk

  ۳. باز کردن پوشهٔ پروژه:
     می‌توانید پوشه را در VS Code باز کنید (File ← Open Folder) و از
     منوی Terminal ← New Terminal پنجرهٔ ترمینال بسازید؛ یا مستقیماً
     در پوشهٔ پروژه، نوار آدرس File Explorer را کلیک کنید، «powershell»
     تایپ و Enter بزنید تا PowerShell همین‌جا باز شود.

  ۴. نصب دقیق وابستگی‌ها (در ریشهٔ پروژه، یعنی جایی که package.json
     هست):

         npm ci

     این دستور دقیقاً همان نسخه‌هایی را نصب می‌کند که پروژه با آن‌ها
     تست شده. چند دقیقه طول می‌کشد.

  ۵. اجرای محیط توسعه:

         npm run dev

     آدرس محلی (معمولاً http://localhost:5173) در خروجی چاپ می‌شود؛
     آن را در مرورگر باز کنید. هر تغییری در فایل‌ها بدهید، صفحه خودکار
     به‌روز می‌شود.

  ۶. توقف سرور توسعه:
     در همان پنجرهٔ PowerShell کلیدهای Ctrl+C را بزنید و به سؤال
     تأیید، Y بگویید (یا پنجره را ببندید).

  ۷. اجرای تست‌های خودکار (۸۹ تست):

         npm test

     باید «Test Files 7 passed (7)» و «Tests 89 passed (89)» ببینید.

  ۸. ساخت نسخهٔ تولید:

         npm run build

     خروجی در پوشهٔ dist ساخته می‌شود. این همان پوشه‌ای است که روی
     اینترنت منتشر می‌شود.

  ۹. پیش‌نمایش نسخهٔ تولید روی رایانهٔ خودتان:

         npm run preview

     و آدرس نمایش‌داده‌شده (معمولاً http://localhost:4173) را در مرورگر
     باز کنید. برای توقف، Ctrl+C.

▂▂▂ یک هشدار مهم ▂▂▂

دابل‌کلیک کردن فایل index.html راه درستی برای تست این پروژه نیست.
دو دلیل دارد: اول، برنامه با ماژول‌های ES نوشته شده که مرورگرها به‌خاطر
محدودیت‌های امنیتی از فایلِ محلی (file://) اجرا نمی‌کنند؛ دوم، رفتار
Service Worker (که کل قابلیت آفلاین به آن وابسته است) فقط روی آدرس
http/https درست معنا دارد. به همین دلیل همیشه از npm run dev یا
npm run preview استفاده کنید.

همچنین توجه کنید که پیش‌نمایش localhost جایگزین تست نهایی روی HTTPS
نیست؛ رفتار Service Worker و «افزودن به صفحهٔ اصلی» فقط پس از انتشار
واقعی روی GitHub Pages به‌طور کامل قابل ارزیابی است.


──────────────────────────────────────────────────────────────────────────
بخش B — بارگذاری NailDesk روی GitHub
──────────────────────────────────────────────────────────────────────────

ساده‌ترین و مطمئن‌ترین راه برای بارگذاری کل ساختار پوشه‌ها (از جمله
پوشهٔ پنهان .github/workflows که برای انتشار خودکار لازم است)
استفاده از GitHub Desktop است.

  ۱. ساخت/ورود به حساب GitHub:
     به github.com بروید. اگر حساب ندارید، «Sign up» و مراحل ساخت
     حساب رایگان را انجام دهید؛ اگر دارید «Sign in» کنید.

  ۲. نصب GitHub Desktop:
     از desktop.github.com نسخهٔ ویندوز را نصب کنید و با حسابتان
     ورود کنید (File ← Options ← Accounts ← Sign in).

  ۳. ساخت مخزن جدید:
     در github.com روی دکمهٔ + بالای صفحه ← «New repository» کلیک
     کنید. نام پیشنهادی: naildesk (کاملاً حروف کوچک). توضیح دلخواه.
     مخزن را Public بگذارید — GitHub Pages در پلن رایگان فقط برای
     مخزن‌های عمومی فعال است. گزینه‌های «Add a README» و لایسنس را
     نیازی نیست تیک بزنید (پروژه خودش README دارد). «Create
     repository» را بزنید.

     ⚠ توضیح شفاف و مهم: با Public بودن، «فایل‌های سازندهٔ برنامه»
     برای همه قابل مشاهده خواهد بود. این فایل‌ها هیچ دادهٔ شخصی ندارند؛
     اما اگر نمی‌خواهید سورس عمومی باشد، یا باید پلن پولی GitHub
     بخرید (Pages روی مخزن خصوصی) یا از انتشار صرف‌نظر کنید. به هیچ
     عنوان فایل پشتیبان JSON یا اطلاعات مشتری‌ها را داخل مخزن
     قرار ندهید — ممنوعیت این کار در انتهای همین بخش هم آمده است.

  ۴. خارج‌کردن ZIP سورس (اگر هنوز نداده‌اید) و آماده‌سازی پوشه:
     NAILDESK_FINAL_GITHUB_SOURCE.zip را Extract کنید. مطمئن شوید
     پوشهٔ .github (پنهان) هم داخل آن هست. در File Explorer از تب
     «View» گزینهٔ «Hidden items» را فعال کنید تا پوشه‌های نقطه‌دار
     (مثل .github و .gitignore) دیده شوند.

  ۵. افزودن پروژه به GitHub Desktop:
     GitHub Desktop را باز کنید: File ← Add local repository ←
     Choose… و پوشهٔ پروژه را انتخاب کنید. پیام «this directory does
     not appear to be a Git repository» می‌آید؛ روی «create a
     repository» کلیک کنید و نام naildesk را تأیید کنید.

  ۶. نخستین Commit:
     در کادر پایین-چپ GitHub Desktop، خلاصه‌ای مثل «Initial commit:
     NailDesk v1.0.0» بنویسید و دکمهٔ آبی «Commit to main» را بزنید.
     (شاخهٔ پیش‌فرض باید main باشد.)

  ۷. انتشار (Publish):
     دکمهٔ «Publish repository» را بزنید. در پنجرهٔ بازشده نام مخزن
     naildesk، گزینهٔ «Keep this code private» را خالی بگذارید (چون
     Pages رایگان مخزن عمومی می‌خواهد) و «Publish Repository» را
     تأیید کنید.

  ۸. بررسی کامل بودن فایل‌ها:
     در github.com مخزن را باز کنید و بررسی کنید که این‌ها واقعاً
     آپلود شده باشند: پوشهٔ src، پوشهٔ public، پوشهٔ tests،
     package.json، package-lock.json، tsconfig.json، vite.config.ts،
     index.html، README.md و به‌ویژه
     .github/workflows/deploy.yml (در صفحهٔ مخزن، پوشهٔ .github در
     ابتدای فهرست دیده می‌شود؛ اگر نبود، یعنی پوشهٔ مخفی موقع Extract
     یا Add جا مانده است — از مرحلهٔ ۴ دوباره بررسی کنید).

▂▂▂ روش جایگزین: بارگذاری از مرورگر ▂▂▂

اگر نمی‌خواهید GitHub Desktop نصب کنید، می‌توانید در صفحهٔ مخزنِ خالیِ
ساخته‌شده از لینک «uploading an existing file» استفاده کنید و فایل‌ها
را بکشید و رها کنید. دو محدودیت دارد: بارگذاری از طریق مرورگر برای
ساختار پوشه‌ای بزرگ کمی وقت‌گیر است و پوشه‌های خالی (مثل .github/
workflows فقط اگر خالی باشد — که در این پروژه خالی نیست و فایل
deploy.yml داخلش هست) آپلود نمی‌شوند. پس بعد از بارگذاری حتماً وجود
.github/workflows/deploy.yml را در مخزن چک کنید؛ اگر جا افتاده بود،
همان یک فایل را دستی با «Add file ← Upload files» اضافه کنید. برای
ادامه، روش GitHub Desktop توصیه می‌شود.

⚠️ قانون غیرقابل‌مذاکره: هیچ‌وقت فایل پشتیبان JSON (خروجی «خروجی
پشتیبان» برنامه)، اطلاعات مشتری‌ها، دیتابیس محلی یا هر دادهٔ شخصی
دیگری را به مخزن اضافه یا Commit نکنید. مخزن فقط سورس برنامه است.
(فایل .gitignore پروژه هم مسیرهای بی‌اهمیت را از نسخه‌گذاری دور نگه
می‌دارد، ولی مسئولیت نگذاشتن دادهٔ شخصی با شماست.)


──────────────────────────────────────────────────────────────────────────
بخش C — فعال‌سازی GitHub Pages
──────────────────────────────────────────────────────────────────────────

  ۱. در github.com مخزن naildesk را باز کنید؛
  ۲. بالای صفحه روی «Settings» کلیک کنید؛
  ۳. از منوی کناری چپ، بخش «Pages» را باز کنید؛
  ۴. در قسمت «Build and deployment»، گزینهٔ «Source» را از حالت
     «Deploy from a branch» به «GitHub Actions» تغییر دهید؛
  ۵. حالا به تب «Actions» (بالای مخزن) بروید. باید گردش‌کاری با نام
     «Deploy to GitHub Pages» در حال اجرا باشد (چون کمی قبل
     فایل‌ها را Push کرده‌اید). روی آن کلیک کنید و پیشرفت مراحل
     «build» و سپس «deploy» را ببینید؛
  ۶. چند دقیقه صبر کنید تا روی آخرین مرحله تیک سبز ظاهر شود؛
     اگر قرمز شد، روی مرحلهٔ شکسته‌خورده کلیک کنید و لاگ خطا را
     ببینید (بخش I، ردیف اول)؛
  ۷. آدرس نهایی سایت در دو جا قابل مشاهده است: در صفحهٔ موفقیت
     گردش‌کار (کنار environment) یا در Settings ← Pages بالای صفحه.

▂▂▂ دربارهٔ قالب آدرس ▂▂▂

آدرس سایتِ پروژه (project site) این قالب را دارد:

    https://USERNAME.github.io/REPOSITORY-NAME/

با نام پیشنهادی مخزن (naildesk) نتیجه چنین است:

    https://USERNAME.github.io/naildesk/

که به‌جای USERNAME نام کاربری گیت‌هابِ خودتان می‌نشیند.

⚠ صادقانه بگوییم: در همین محیط، سایت برای حساب واقعی شما منتشر نشده
است؛ این آدرس «الگو» است نه لینک زنده. آدرس واقعی را فقط بعد از
اجرای موفق مراحل بالا از صفحهٔ Settings ← Pages خودتان بردارید.

چرا برنامه زیر این زیرمسیر درست کار می‌کند؟ چون مسیر پایهٔ ساخت روی
«./» نسبی تنظیم شده، آدرس‌های فونت نسبی هستند، مانیفست PWA با
start_url و scope نسبی تعریف شده و ناوبری داخل برنامه مبتنی بر تب
است (نه آدرس URL)؛ پس باز شدن مستقیم سایت زیر /naildesk/ هیچ مشکلی
ایجاد نمی‌کند.


──────────────────────────────────────────────────────────────────────────
بخش D — فرستادن وب‌سایت به ناخن‌کار
──────────────────────────────────────────────────────────────────────────

  ۱. آدرس واقعی و HTTPS منتشرشده را (از Settings ← Pages) کپی کنید؛
  ۲. آن را برای ناخن‌کار بفرستید (پیام‌رسان، ایمیل و…)؛
  ۳. از او بخواهید حتماً روی آیفون و با مرورگر Safari بازش کند؛
  ۴. یادآوری کنید که نخستین بارگذاری اینترنت می‌خواهد و باید چند
     لحظه بماند تا پیام «برنامه برای استفاده آفلاین آماده است.»
     ظاهر شود؛
  ۵. تفاوت را روشن کنید: «باز کردن سایت» یعنی استفاده مثل یک
     وب‌سایت معمولی؛ «نصب» (بخش E) یعنی افزودن به صفحهٔ اصلی برای
     اجرای اپ‌مانند و آفلاین. هر دو به همان آدرس نیاز دارند، اما
     نصب یک قدم دستی اضافه دارد که فقط خود کاربر می‌تواند انجام
     دهد.


──────────────────────────────────────────────────────────────────────────
بخش E — افزودن NailDesk به صفحهٔ اصلی آیفون
──────────────────────────────────────────────────────────────────────────

  ۱. NailDesk را با Safari باز کنید (آدرس HTTPS سایت)؛
  ۲. صبر کنید تا نوار «برنامه برای استفاده آفلاین آماده است.» دیده
     شود و بعد آن را با ✕ ببندید؛
  ۳. روی دکمهٔ Share در نوار پایینِ Safari (مربع با فلش رو به بالا)
     بزنید؛
  ۴. در فهرست بازشده، روی «Add to Home Screen» بزنید؛
     (در iOSهای جدید ممکن است ابتدا «Add to Home Screen» زیر
     «…»های بیشتر پنهان باشد — به پایین فهرست اسکرول کنید؛
     راه‌حل بیشتر در بخش I)؛
  ۵. اگر گزینهٔ «Open as Web App» نمایش داده شد، فعالش کنید؛
  ۶. روی «Add» بزنید؛
  ۷. آیکون NailDesk (بطری لاک صورتی) حالا روی صفحهٔ اصلی است؛
  ۸. برنامه را از همان آیکون باز کنید؛ حالا تمام‌صفحه و بدون نوار
     مرورگر اجرا می‌شود؛
  ۹. راه‌اندازی اولیه را کامل کنید (نام و…)؛
  ۱۰. برای اطمینان از آمادگی آفلاین، یک‌بار دیگر بازش کنید و منتظر
      پیام «برنامه برای استفاده آفلاین آماده است.» بمانید (یا
      تست بخش F را انجام دهید).

⚠ صداقت فنی: هیچ وب‌سایت معمولی نمی‌تواند خودش را بدون اقدام دستیِ
کاربر روی صفحهٔ اصلی آیفون نصب کند؛ این محدودیت خود iOS است، نه نقص
برنامه. «Add to Home Screen» یک بار انجام می‌شود و بعد از آن، باز
کردن برنامه فقط با یک لمس روی آیکون است.


──────────────────────────────────────────────────────────────────────────
بخش F — تست آفلاین روی آیفون
──────────────────────────────────────────────────────────────────────────

این تست را فقط با «اطلاعات آزمایشی» انجام دهید؛ تا وقتی موفق نشده
است، دادهٔ واقعی مشتری وارد نکنید.

  ۱. برنامهٔ نصب‌شده را باز کنید (اینترنت روشن)؛
  ۲. صبر کنید پیام «برنامه برای استفاده آفلاین آماده است.» ظاهر شود؛
  ۳. Control Center را باز کنید و «Airplane Mode» را روشن کنید؛
  ۴. برنامه را کامل ببندید (از App Switcher بالا بکشید) و دوباره از
     آیکون باز کنید؛
  ۵. تب «مشتریها» را باز کنید — باید فهرست (حتی خالی) بدون خطا بیاید؛
  ۶. یک مشتری آزمایشی بسازید (مثلاً «تست ۱»)؛
  ۷. تب «طراحی» را باز کنید، رنگ یک ناخن را عوض کنید و صبر کنید
     بالای صفحه «ذخیره شد» بنشیند؛ سپس طرح را با عنوان «تست آفلاین»
     ذخیره کنید؛
  ۸. تب «تقویم» — یک نوبت آزمایشی برای فردا بسازید؛
  ۹. ماشین‌حساب را باز کنید و یک محاسبهٔ ساده انجام دهید؛
  ۱۰. تنظیمات ← «داده‌ها و پشتیبان‌گیری» را باز کنید — صفحه باید
      کامل بیاید (خودِ دانلود پشتیبان در حالت آفلاین هم کار می‌کند،
      چون فایل به‌صورت محلی ساخته می‌شود)؛
  ۱۱. اگر همهٔ مراحل بدون خطا بودند، تست موفق است.

پاک‌سازی اطلاعات تست: مشتری و نوبت تست را از همان صفحات حذف کنید
(دکمهٔ حذف با تأیید) و طرح «تست آفلاین» را از گالری حذف کنید.
اگر ترجیح می‌دهید همه‌چیز یک‌جا پاک شود: تنظیمات ← منطقهٔ خطر ←
«پاک کردن همه داده‌ها» (نیاز به تایپ عبارت «پاک کن»)؛ اما قبلش از
داده‌های مهم‌تان پشتیبان بگیرید.


──────────────────────────────────────────────────────────────────────────
بخش G — پشتیبان‌گیری و بازیابی (روی آیفون)
──────────────────────────────────────────────────────────────────────────

  گرفتن پشتیبان:
  ۱. تنظیمات ← «داده‌ها و پشتیبان‌گیری» ← «خروجی پشتیبان»؛
  ۲. Safari پنجرهٔ دانلود را باز می‌کند؛ «Save to Files» را بزنید؛
  ۳. مقصد را انتخاب کنید — مثلاً «On My iPhone» و یک پوشهٔ دلخواه،
     یا iCloud Drive (تا روی دستگاه‌های دیگر اپل هم باشد)؛
  ۴. فایلی به نام naildesk-backup-YYYY-MM-DD.json ذخیره می‌شود.

  بازیابی:
  ۱. همان صفحه ← «بازیابی از فایل»؛
  ۲. فایل را از Files انتخاب کنید؛
  ۳. برنامه فایل را اعتبارسنجی می‌کند — اگر سالم باشد خلاصهٔ محتوا و
     پیشنهادِ «پشتیبان اضطراری از داده‌های فعلی» را می‌بینید؛
     اگر معیوب باشد، فقط فهرست خطاها را می‌بینید و چیزی تغییر
     نمی‌کند؛
  ۴. تأیید نهایی («بله، بازیابی کن») — جایگزینی اتمی انجام می‌شود.

  توصیه‌ها:
  • هر هفته یا بعد از هر موج ورود دادهٔ جدید پشتیبان بگیرید؛
  • چند نسخهٔ اخیر را نگه دارید (فایل‌ها اسمِ تاریخ دارند و روی هم
    نمی‌افتند)؛
  • قبل از «بازیابی»، از داده‌های فعلی پشتیبان بگیرید تا در صورت
    پشیمانی قابل برگشت باشد — بازیابی «جایگزینی کامل» است، نه
    ادغام؛
  • نگه‌داشتن یک نسخه در iCloud Drive (یا هر جای دومِ امن) در برابر
    گم‌شدن/خرابی گوشی بیمهٔ خوبی است.

  چرا چند نسخه؟ چون اگر یک فایل در اثر خرابی حافظه یا انتقال ناقص
  آسیب ببیند، نسخهٔ قبلی نجات‌تان می‌دهد؛ اعتبارسنجی برنامه فایلِ
  خراب را تشخیص می‌دهد اما نمی‌تواند محتوای ازدست‌رفته را برگرداند.


──────────────────────────────────────────────────────────────────────────
بخش H — به‌روزرسانی وب‌سایت
──────────────────────────────────────────────────────────────────────────

وقتی خواستید نسخهٔ جدیدی از برنامه (مثلاً با تغییرات یا اصلاحات) منتشر
کنید:

  ۱. فایل(های) موردنظر پروژه را در رایانه تغییر دهید؛
  ۲. در GitHub Desktop تغییرات را بنویسید و «Commit to main» بزنید؛
  ۳. «Push origin» را بزنید تا به github.com برود؛
  ۴. GitHub Actions به‌طور خودکار دوباره build می‌کند: تست‌ها →
     ساخت → انتشار dist؛
  ۵. در تب Actions منتظر تیک سبز بمانید؛
  ۶. روی آیفون، برنامهٔ نصب‌شده را باز کنید؛
  ۷. اگر نسخهٔ جدید آماده باشد، نوار «نسخه جدید NailDesk آماده است.»
     با دکمهٔ «به‌روزرسانی» ظاهر می‌شود — کاربر دکمه را بزند تا
     اعمال شود (برنامه هرگز خودسر وسط کار ری‌لود نمی‌کند)؛
  ۸. بعد از به‌روزرسانی، چند بار بین صفحات بروید و مطمئن شوید
     مشتری‌ها، نوبت‌ها و طرح‌ها سر جایشان هستند. به‌روزرسانی فقط
     «فایل‌های برنامه» را عوض می‌کند و به بانک اطلاعاتی دست نمی‌زند.

  اهمیت ثابت ماندن آدرس: بانک اطلاعاتی مرورگر به «مبدأ» (همان آدرس
  سایت) گره خورده است. اگر نام کاربری گیت‌هاب عوض شود، مخزن با نام
  دیگری ساخته شود یا دامنهٔ متفاوتی استفاده کنید، آدرس عوض می‌شود و
  مرورگر آن را یک «سایت دیگر» می‌بیند با بانک خالیِ جدید. پس:
  • همان مخزن و همان نام را نگه دارید؛
  • اگر مجبور به جابه‌جایی شدید، قبل از تغییر از برنامهٔ قدیمی
    «خروجی پشتیبان» بگیرید و در آدرس جدید «بازیابی از فایل» کنید.

  نکتهٔ فنی برای توسعه‌دهنده: اگر Service Worker به‌روزرسانی را
  نشان نداد، بستن کامل برنامه (از App Switcher) و باز کردن دوباره
  کمک می‌کند؛ Safari در باز شدن بعدی نسخهٔ جدید را فعال می‌کند.


──────────────────────────────────────────────────────────────────────────
بخش I — عیب‌یابی
──────────────────────────────────────────────────────────────────────────

  ۱) GitHub Actions شکست می‌خورد
     — تب Actions ← اجرای قرمز ← مرحلهٔ خطا. معمول‌ترین‌ها:
     • «npm ci» خطا می‌دهد: مخزن با package-lock.json ناقص آپلود
       شده؛ مطمئن شوید package-lock.json واقعاً در مخزن هست.
     • مرحلهٔ «Run tests» قرمز است: تستی شکسته؛ روی مرحله کلیک
       کنید و نام تست را ببینید؛ اگر روی پروژهٔ اصلی چیزی تغییر
       نداده‌اید، مطمئن شوید همهٔ فایل‌های src و tests کامل آپلود
       شده‌اند.
     • مرحلهٔ «Build» قرمز است: خطای TypeScript؛ تغییرات محلی خودتان
       را قبل از Push با «npm run build» روی رایانه بسازید و خطا را
       ببینید.

  ۲) GitHub Pages خطای ۴۰۴ می‌دهد
     — Settings ← Pages ← Source واقعاً «GitHub Actions» باشد؛
     — آدرس را دقیق با حروف کوچک بنویسید (USERNAME و naildesk)؛
     — تب Actions را چک کنید که آخرین اجرا سبز باشد؛ ۴۰۴ یعنی هنوز
       چیزی منتشر نشده.

  ۳) CSS یا جاوااسکریپت لود نمی‌شود (صفحهٔ خام/سفید)
     — مسیر پایهٔ ساخت روی ./ نسبی است، پس این حالت فقط وقتی رخ
       می‌دهد که dist با تنظیم دیگری ساخته شده باشد؛ vite.config.ts
       را دست‌نخورده نگه دارید؛
     — اگر صفحات را دستی جابه‌جا کرده‌اید، ساخت را دوباره و بدون
       تغییر انجام دهید: npm run build و مجدداً Push.

  ۴) برنامه نصب نمی‌شود / «Add to Home Screen» پیدا نمی‌شود
     — حتماً با Safari باز کنید (نه Chrome آیفون)؛
     — دکمهٔ Share ← در فهرست، به پایین اسکرول کنید؛ اگر باز هم
       نیست، در iOS جدید ممکن است لازم باشد از «…» آخر فهرست،
       «Add to Home Screen» را به منوی Share اضافه کنید (Edit
       Actions)؛
     — اگر Safari در حالت «Private Browsing» است، از حالت عادی
       استفاده کنید.

  ۵) اجرای آفلاین شکست می‌خورد
     — پیام «برنامه برای استفاده آفلاین آماده است.» را قبل از
       قطع اینترنت دیده‌اید؟ اگر نه، چند دقیقه آنلاین بمانید و
       صفحه را یک‌بار رفرش (نوار آدرس ← آیکون چرخش) کنید؛
     — Settings ← Safari ← Advanced ← Website Data (در برخی
       نسخه‌ها) نباید برای این سایت پاک شده باشد؛
     — اگر «Clear History and Website Data» زده باشید، کش برنامه و
       بانک پاک می‌شود — پشتیبان برگردانید (بخش G).

  ۶) مشکل به‌روزرسانی Service Worker
     — برنامه را کامل ببندید و دوباره باز کنید؛
     — اگر نوار «نسخه جدید» آمد، دکمهٔ «به‌روزرسانی» را بزنید و
       چند ثانیه صبر کنید؛
     — آخرین راه: از صفحهٔ اصلی، آیکون را نگه دارید، «Remove App»
       (حذف از صفحهٔ اصلی — نه «Delete App») را بزنید و دوباره
       Add to Home Screen کنید؛ داده‌ها می‌مانند چون به Safari
       وابسته‌اند نه به آیکون.

  ۷) داده‌ها نمایش داده نمی‌شوند
     — آیا موقع کار در حالت ناشناس (Private) بوده‌اید؟ آن حالت
       داده را بعد از بستن دور می‌ریزد؛
     — آیا آدرس دیگری باز کرده‌اید؟ بانک به آدرس سایت گره خورده
       (بخش H)؛
     — Settings ← Safari ← «Clear History and Website Data» داده‌ها
       را پاک می‌کند — بازیابی از فایل پشتیبان (بخش G).
     — اگر همه‌جا خالی بود ولی فایل پشتیبان دارید، جای نگرانی
       نیست: «بازیابی از فایل» همه‌چیز را برمی‌گرداند.

  ۸) پشتیبان گم شده / پیدا نمی‌شود
     — در برنامهٔ Files آیفون، روی Browse ← «On My iPhone» یا
       «iCloud Drive» و پوشه‌ای که هنگام «Save to Files» انتخاب
       کردید بروید؛ نام فایل با naildesk-backup شروع می‌شود؛
     — در Files می‌توانید روی «Search» بزنید و بنویسید:
       naildesk-backup

  ۹) بازیابی JSON شکست می‌خورد
     — برنامه پیام‌های دقیق می‌دهد: «این فایل پشتیبان NailDesk
       نیست» یعنی فایل دیگری انتخاب شده؛ «نسخهٔ ساختار پشتیبانی
       نمی‌شود» یعنی فایل از نسخهٔ آیندهٔ برنامه است؛ خطاهای رکوردی
       (نام نامعتبر، قیمت نامعتبر و…) یعنی فایل دستکاری یا ناقص
       منتقل شده؛
     — فایل را دوباره از محل اصلی کپی کنید و مطمئن شوید پسوندش
       json. است؛
     — هیچ‌وقت محتوای فایل را دستی ویرایش نکنید؛
     — در همهٔ این حالت‌ها داده‌های فعلی شما دست‌نخورده مانده‌اند؛
       بازیابی فقط بعد از اعتبارسنجی موفق و تأیید شما انجام می‌شود.

  ۱۰) GitHub Pages به‌روز نمی‌شود
     — تب Actions: آیا Push جدید شما واقعاً Commit و Push شده؟
       (در GitHub Desktop دکمهٔ «Push origin» را بزنید)؛
     — اجرای آخر سبز است؟ اگر قرمز است، ردیف ۱؛
     — مرورگر آیفون ممکن است نسخهٔ کش‌شده را نشان دهد: صفحه را
       رفرش کنید یا نوار به‌روزرسانی برنامه را ببینید.

  ۱۱) آیکون از صفحهٔ اصلی حذف شده
     — آیکون حذف‌شده فقط میانبر است؛ داده‌ها سالم‌اند. دوباره
       سایت را در Safari باز کنید و Add to Home Screen بزنید؛
       برنامه با همان داده‌های قبلی بالا می‌آید (چون همان آدرس
       است)؛
     — فقط اگر «Delete App» کامل زده باشید و داده پاک شده باشد،
       به پشتیبان نیاز دارید.
